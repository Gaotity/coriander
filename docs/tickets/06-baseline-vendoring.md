# 06 — Baseline data vendoring + license manifest

**Parent spec:** [docs/spec/mvp.md](../spec/mvp.md)
**Blocked by:** 01
**Status:** done

## What to build

Choose the baseline schema set (rime-prelude + one starter schema + essay + opencc data), vendor it into the app bundle with a license manifest covering every bundled asset. Record the prebuilt-artifacts vs deploy-on-first-seed decision here (informed by ticket 05's timing measurements).

## Acceptance criteria

- [x] Baseline set chosen and vendored into the bundle — rime-prelude (4 core yamls), rime-luna-pinyin (5 schemas + dict + pinyin.yaml), rime-essay (essay.txt), OpenCC (all config jsons + 16 generated .ocd2)
- [x] License manifest lists every bundled Rime asset — `vendor/rime-baseline/LICENSE-MANIFEST.md` (LGPL-3.0 ×3 upstreams, Apache-2.0 OpenCC)
- [x] Bundle size recorded — baseline payload **7.7 MB / 43 files** (essay.txt 5.7 MB, opencc 1.2 MB, luna dict 0.9 MB)
- [x] Prebuilt-vs-deploy-on-seed decision recorded with rationale — **raw YAML + first-launch in-app Deploy** (see Results)

## Results

- Sources pinned by SHA (`scripts/rime-data/fetch-data.sh`); vendoring is one script: `scripts/rime-data/vendor-baseline.sh`.
- OpenCC `.ocd2` dictionaries are **not** downloadable from rime — they are generated by the `opencc_dict` host tool. The script host-builds the tools from librime's opencc submodule (temporarily restoring the tools/data subdirs that the iOS build sed-disables; the iOS script re-patches idempotently) and runs the data generation — zero external downloads.
- Bundle wiring: `project.yml` adds `vendor/rime-baseline` as a folder-type source, so the directory lands verbatim at `Coriander.app/rime-baseline/` (verified in the built product).
- **Decision: ship raw YAML and Deploy in the Container App on first launch.** Rationale: ticket 01 measured seed *copying* at 0.03 s — irrelevant either way; prebuilt artifacts would require a host (macOS) librime build purely to run Deploy offline, doubling the toolchain for zero user-visible gain; first-launch in-app Deploy is ADR-0001's native shape and gets a progress UI anyway (ticket 18). Ticket 05's Deploy timing may revisit this if Deploy turns out pathological, but nothing so far suggests it.
- Note: the iOS deps build and the host opencc-tools build share the submodule checkout; the two sed states are managed by the scripts — run them in any order.
